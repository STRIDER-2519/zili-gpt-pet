# 开发与素材维护

## 素材工具

需要 Python 3.10 或更新版本，安装依赖：

```text
python -m pip install -r requirements.txt
python tools/pet_assets.py validate
```

工具使用项目相对路径，不依赖制作者的电脑、插件缓存、账号或 API Key。

```text
# 导出所有 73 个 192x208 透明帧
python tools/pet_assets.py extract --output build/frames

# 修改现有帧后重新组装 v2 图集
python tools/pet_assets.py compose --frames build/frames --output build/spritesheet.png

# 检查自制图集的基本布局；跳过原发行文件哈希
python tools/pet_assets.py validate --atlas build/spritesheet.png --skip-manifest

# 生成九组状态预览、三跳回待机预览和看向循环
python tools/pet_assets.py preview --output build/previews
```

`validate` 检查尺寸、RGBA、编码、必需格和空白格，并核对交付清单的哈希；它不是原生宠物的完整验收工具，也不能代替有序帧视觉检查。当前成品此前已完成原生 Pets 校验及独立视觉审阅，摘要见 `verification/quality-summary.json`。

普通状态 GIF 按制作规范时长循环展示。额外的 `native-idle-jump3-idle.gif` 使用本次核实的原生慢速待机与三遍跳跃时序；这不是实时界面录屏。

## 继续制作画面

采用的生成源图在 `source-art/`，实际提示词在 `prompts/`。源条带不是可直接导入的成品；原生导入使用 `pets/zili-gpt-pet/spritesheet.png`。

新画面通过图像生成工具制作，再统一尺度、背景、定位与基线。重新生成会产生差异；此仓库没有承诺通过提示词可逐像素重现原图，也不附带第三方插件运行库。修改后应检查所有受影响状态及衔接，并用宿主当前的校验流程重新接受图集。

发行图集采用固定哈希以防安装到损坏素材。若自行发布新图集，应同步更新 `tools/install-pet.ps1` 中的 `expectedHash`、`verification/artifact-manifest.json` 与版本说明。

## 编译 Windows 面板

在 Windows PowerShell 中、项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\companion\build.ps1
```

输出位于 `build/panel/`。编译使用系统 .NET Framework 64 位 C# 编译器，不需要 Python 或 NuGet。完整复制输出目录中的 EXE、XAML 与 assets 才能运行。

执行已有计时、界面和冒烟检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\companion\test.ps1
```

测试输出位于 `build/`，不访问已经安装的面板用户记录。图形界面检查需要可运行 WPF 的 Windows 桌面环境。分发运行包时排除 `data/`、`smoke-data/`、测试 EXE 和诊断日志。

## 原生本地安装脚本

原生格式为 `pets/<目录>/pet.json` 加相对 PNG。安装脚本只复制两份本项目文件；它不调用云端 Pets、不修改原生安装包，也不自动改变当前选择。

可显式指定客户端实际的 pets 目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install-pet.ps1 -PetsDirectory 'D:\自定义客户端目录\pets'
```

本地安装脚本的回归检查使用临时的项目内目录，不写入制作者实际 `.codex/pets`。
