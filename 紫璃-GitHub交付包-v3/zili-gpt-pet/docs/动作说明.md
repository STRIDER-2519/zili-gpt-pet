# 动作与触发

以下规则在 2026-10-11 对 Windows 原生客户端 26.1007.2314.0 的相关代码作只读核对。它们说明该版本的行为，后续客户端版本可能不同。公开包只保留结论，不附带宿主代码。

| 条件 | 紫璃动作 |
| --- | --- |
| 无当前活动通知、普通提示或短动作播放结束 | 趴卧休息 |
| 鼠标进入角色区域，且没有拖动状态覆盖 | 直立小跳 |
| 拖动时横向采样位移约达 4 像素 | 对应方向跑步 |
| 初次唤醒通知 | 挥手 |
| 当前首条通知表示任务处理中 | 思考工作 |
| 当前首条通知表示等待输入或审批 | 虎头帽与拨浪鼓 |
| 当前首条通知表示受阻或失败 | 低落反应 |
| 当前首条通知表示结果准备好 | 检查成果 |
| 有鼠标看向帧，且有效状态为待机、工作或招手 | 对应看向方向覆盖普通动画 |
| 单击 | 原生入口或快速聊天；未见独立点击跳跃逻辑 |

优先级：**拖动等临时状态 > 鼠标悬停 > 当前首条活动通知的基础状态**。

## 为什么以前会趴着跳

旧跳跃行的首尾是趴姿。原生悬停默认连续播放该行三遍，所以每遍都会趴下、撑起、跳起再趴下。当前 v3 只重做跳跃行，五帧改为直立准备、离地、腾空、落地、站稳；趴卧只放在独立待机行。

## 时序与限制

- 默认跳跃三遍约 2.52 秒，然后接待机尾段；持续悬停不会一直跳。
- 其他非待机标准动作也默认播三遍，再接待机尾段；看到趴卧不一定表示后台任务已经结束。
- 待机一轮约 6.6 秒。
- 鼠标移出、拖动或状态变化会立即切换画面，可能中断当前跳跃。图集无法强制先落地再切换。
- 现有看向方向为站姿；从趴卧待机切到看向鼠标仍可能直接变为站姿。
- 虎头帽拨浪鼓是“等待输入”动作，不是按闲置分钟数随机触发的彩蛋。
- 减少动态效果模式会使用静态帧。

图集只改变外观；不能配置鼠标触发、冷却、动作次数、任务优先级或按入口分别设计的过渡。
